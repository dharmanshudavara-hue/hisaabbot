01 Overview

Problem statement

A large segment of India's working population — small traders, daily-wage earners, farmers, and household workers — manages significant financial transactions entirely from memory. They lend and borrow money, track daily expenses, and operate informal credit networks, all verbally with no written record.

This creates three hard problems: memory failure (forgotten loans lead to disputes), no proof (word-of-mouth transactions leave no evidence), and no awareness (no visibility into total debt owed or owed to them). Existing apps — KhataBook, OkCredit, even WhatsApp — all require literacy, a barrier that excludes this entire segment.

The specific user: An adult male, primary earner in a household, who conducts 10–30 small-money transactions per week — borrowing, lending, or daily spend — and cannot read or write in any language.

Product vision

HisaabBot is a voice-first progressive web app that lets any person manage their finances entirely by speaking in their own language. No typing. No reading. No forms. The user speaks a transaction — "Ramesh ne 500 rupya liya" — and the app understands, stores, and confirms it back in their voice.

One-line product statement: HisaabBot is the financial memory that non-literate Indians never had — a voice assistant that remembers every rupee, reminds you of every due date, and requires zero reading ability to use.
Build constraint: The entire product must be built and operated at ₹0 cost using free-tier tools only. This is a hard constraint for v1.0, not a preference.

02 Users & Personas

👨
Ramjibhai
Primary User · Non-literate adult
Profile

55 years old, small vegetable vendor in Ahmedabad. Earns ₹300–600/day, conducts 5–15 informal money transactions per week.

Tech access

Has a basic Android phone (₹5,000–8,000), uses WhatsApp for voice messages, comfortable speaking but never types.

Goals

Know who owes him money. Remember when to collect. Avoid disputes. Not feel embarrassed about being unable to write.

Frustrations

Forgets loans after 2–3 weeks. Has no proof when disputes arise. Relies on his son to track things, which limits autonomy.

👦
Dharmanshu
Secondary User · Literate caretaker
Profile

College student, son of the primary user. Occasionally helps father with finances. Has smartphone, full literacy.

Tech access

Uses Android + laptop, comfortable with apps, sets up the app for father, occasionally reviews family finances.

Goals

Set up the app once and have it run itself. Get alerts when large loans are due. Export records for important disputes.

Frustrations

Can't always be available to help. Doesn't want a complicated system his father will stop using after a week.

04 Features

Priority key: MUST = required for launch   SHOULD = strongly desired   COULD = nice to have

F1 — Voice Input Engine

The foundational feature. Everything else depends on this working reliably in Hindi and Gujarati. User holds a button, speaks naturally, and the app extracts structured data from natural speech.

F1.1
Speech capture via Web Speech API
App must capture voice input using the browser's native Web Speech API. User holds a large microphone button to record. Recording stops when they release or after 10 seconds of silence.
MUSTWeb Speech API
F1.2
AI intent extraction (Groq free tier)
Transcribed text is sent to Groq's free Llama 3.1 API. A structured prompt extracts: transaction_type (lent/borrowed/spent), person_name, amount (INR), due_date (if mentioned), category (for expenses). Returns JSON.
MUSTGroq API · Free tier
F1.3
Voice confirmation playback
After saving a transaction, the app speaks a confirmation in the user's language using the SpeechSynthesis API. Example: "Ramesh ka 500 rupya ka udhar save ho gaya, 2 hafte baad dega."
MUSTSpeechSynthesis API
F1.4
Ambiguity correction flow
If the AI cannot extract a required field (e.g. amount missing), the app asks a targeted follow-up question by voice: "Kitne rupaye?" User responds to fill the gap. Max 2 clarification rounds.
SHOULD
F1.5
Language selection
User can set preferred language (Hindi / Gujarati / English) in settings. All STT, AI prompts, TTS confirmations, and UI labels adapt to the chosen language.
MUST

F2 — Loan Tracker (Udhar Khata)

F2.1
Record loan by voice
User can record who lent or borrowed money, how much, and an optional due date — entirely by speaking. System distinguishes "I lent" vs "I borrowed" correctly.
MUST
F2.2
View outstanding loans by voice
User can ask "Kaun mujhe paisa dega?" or "Maine kisko paisa diya?" The app reads the answer aloud: "Ramesh ₹500, Suresh ₹1200 — kul ₹1700 tumhara milna hai."
MUST
F2.3
Mark loan as repaid
User can say "Ramesh ne paisa de diya" and the loan is marked settled with a timestamp. Repaid loans move to a history view.
MUST
F2.4
Simple interest calculator
Optional field: monthly interest rate (%). App automatically calculates interest accumulated since loan date and includes it in the outstanding amount.
SHOULD
F2.5
PDF proof export
A "Generate Proof" button creates a simple PDF (via jsPDF, open source) listing the loan: names, amount, date, and repayment status. Sharable via WhatsApp for dispute resolution.
SHOULDjsPDF · Free

F3 — Expense Tracking

F3.1
Record daily expense by voice
User can say "Aaj doodh aur sabzi pe 120 rupaye gaye" and the app saves ₹120 as a food/grocery expense for today.
MUST
F3.2
Auto-categorization
AI automatically assigns a category from: Food, Transport, Medicine, House, Business, Other. No manual selection required.
SHOULD
F3.3
Daily total by voice
User asks "Aaj kitna kharch hua?" and the app responds with today's total and a breakdown by category.
SHOULD

F4 — Reminders & Notifications

F4.1
Telegram due-date reminders
A Telegram bot (free, no business account needed) sends a message when a loan is due in 3 days and on the due date. Message in user's chosen language: "Kal Ramesh ka ₹500 milna chahiye tha."
MUSTTelegram Bot API · Free
F4.2
Browser push notifications
If user doesn't use Telegram, PWA push notifications (Web Push API) send the same reminders as native-style notifications on Android.
SHOULDWeb Push API · Free

F5 — Reports & Summaries

F5.1
Monthly voice report
On the 1st of each month, the app generates a 30-second spoken summary via Groq + SpeechSynthesis: "Pichhle mahine aapne ₹3,200 liye aur ₹1,500 diye. Kharche mein sabse zyada ₹800 khana tha."
SHOULD
F5.2
Family view (literate caretaker)
A secondary screen (password-protected) shows a simple visual dashboard — bar charts, total figures — for literate family members who want to review finances.
COULD

F6 — Accessibility & UX

F6.1
Icon-only navigation
All core screens must be accessible using only icons and color cues. No text label should be required to understand a button. 4 core icons on home: 🎙️ Speak · 💰 Loans · 🔔 Alerts · 📊 Reports.
MUST
F6.2
Large tap targets
All interactive elements must be at least 56×56px. Primary microphone button must be at least 72×72px. Minimum text size 18px where shown.
MUST
F6.3
Haptic feedback
Android haptic vibration on: mic start, successful save, error. Reinforces actions for users who may not look at screen.
SHOULD
F6.4
Installable as PWA
App must pass PWA criteria (manifest.json, service worker, HTTPS) so it shows the "Add to Home Screen" prompt on Android Chrome. User should interact via a home screen icon, not a browser URL.
MUST

05 User Stories

Recording a loan

As Ramjibhai (primary user), I want to tell the app that I lent money to someone by just speaking their name and amount, so that I never forget about it and can ask for it back later with confidence.
Given I open the app and press the microphone button, when I say "Ramesh ne mujhse 500 liye, 2 hafte mein dega," then the app should save a loan record and speak back: "Ramesh ka ₹500 save ho gaya, 2 hafte baad milega."

Checking who owes money

As Ramjibhai, I want to ask the app who still owes me money without looking at any screen, so that I can decide who to follow up with today.
Given I have 3 outstanding loans recorded, when I say "Kaun mujhe paisa dena hai?" then the app should read all names and amounts aloud and tell me the total.

Receiving a reminder

As Ramjibhai, I want to receive a Telegram message the day before a loan is due, so that I remember to collect it without having to check the app manually.

Caretaker reviewing finances

As Dharmanshu (caretaker), I want to open a summary screen and see all my father's recorded loans and monthly spending, so that I can help him understand his finances and spot any issues.

Generating proof

As Ramjibhai, I want to generate a simple document showing a loan I gave to someone, so that if they deny it I can show it to a community elder or family member as evidence.

08 Technical Architecture

Free stack map

Voice request flow
🎤 USER SPEAKS → Web Speech API (browser native, free ∞)
↓ transcript text
⚡ VERCEL EDGE FUNCTION → validates + rate-limits → calls Groq
↓ POST /v1/chat/completions
🧠 GROQ API (Llama 3.1 70B) → intent extraction → JSON response (free: 14,400 req/day)
↓ { type, person, amount, date }
🗄️ SUPABASE POSTGRES → insert record with user_id + timestamp (free: 500MB)
↓ success ack
🔊 SpeechSynthesis API → speaks confirmation in user's language (browser native, free ∞)
Offline fallback: If no internet is detected, the Vercel call is skipped. The raw transcript is stored in IndexedDB with status: "pending_ai". When connection returns, a service worker processes the backlog through Groq and syncs to Supabase. The user hears a local cached confirmation immediately to avoid confusion.

10 Risks & Mitigations

RiskLevelMitigation
Gujarati STT accuracy on regional accents
Web Speech API may misrecognize Gujarati dialect variations		 High Fallback: user can tap to correct a word. Confidence score below 0.7 triggers "please repeat" prompt. Optional Whisper local model for better accuracy.
Groq API rate limit hit
14,400 req/day free limit exceeded with many users		 Medium Fallback to Google Gemini 1.5 Flash free tier (1M tokens/day). Cache common patterns locally. Limit to ~50 pilot users in v1.0.
User drops off after onboarding
Target users may find initial setup confusing		 Medium 2-minute Gujarati onboarding video. Caretaker sets up once. 5 "quick start" example commands shown on first launch.
Offline sync conflicts
Same record edited offline and online simultaneously		 Medium App is append-only for v1.0 — records are never edited after creation, only marked settled. Eliminates most conflict scenarios.
Supabase free tier limit
500MB database limit		 Low Each transaction record is ~500 bytes. 500MB = 1M records — sufficient for thousands of pilot users for years.
Web Speech API browser support
Not supported on Firefox or older Android		 Low Chrome is dominant on Android India (85%+ market share). App onboarding explicitly states "requires Chrome browser."
